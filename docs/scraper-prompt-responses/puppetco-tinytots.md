## Summary
Paste this in as `scripts/scrapers/puppetco.py`. It's tested against reconstructed HTML matching what I actually pulled from the live pages — including the three different messy formatting patterns the site's editors used (clean `<br>`-separated title/description/time blocks, text that runs into the time trigger with zero separating whitespace, and inline `"Title, always at 10am!"` with no colon at all).
Two things to keep in mind as the maintainer:

1. `ARTIST_EVT_IDS` is the fragile part. There's no way to crawl the ShoWare ticketing site's list of active shows without JS execution, so I hand-mapped the 5 guest artists currently on `/tiny-tots` to their `evt=` ids. The scraper self-prunes (an artist removed from `/tiny-tots` just stops getting fetched), but a new guest artist won't be picked up automatically — you'd need to find their `evt=` id (searching `site:thepuppetco.showare.com eventperformances.asp` works) and add it to the dict.
2. The JSON-LD check is real but currently unused. I implemented it properly per your instructions in case Puppet Co./Squarespace ever adds structured data, but as of today it finds nothing and every run falls through to the HTML parser.

If either of these limitations is a dealbreaker for how this scraper gets used (e.g., it needs to be fully unattended for months), the more robust long-term fix would be swapping `base.get()` for something that executes JS (Playwright/Selenium) against `thepuppetco.showare.com` directly, which would let you discover active `evt=` ids from the real calendar widget instead of hardcoding them.
